AI Skincare Product Analyzer

An informational decision-support tool that matches skincare products to a person's skin profile, ingredient restrictions, preferences and budget, and explains why each product was chosen.

Team: Keerthana · Prateek · Harsha · Karthik

Problem statement

People differ in skin type, visible concerns, ingredient allergies, sensitivities, preferences and budget. Most product choices still rest on popularity, ratings, advertising or general descriptions, none of which account for an individual's needs. Ingredient lists are long and technical, so comparing products on composition, price and intended use is slow and confusing.

The project builds an analyzer that:

  1. analyses selected visible skin characteristics from a facial image;
  2. processes cosmetic ingredient lists and flags restricted ingredients;
  3. recommends and ranks products using the user's profile, restrictions, category and budget; and
  4. explains each recommendation in plain language.

Research questions

  1. RQ1. How reliably can a transfer-learning image classifier identify a small set of visible skin characteristics from facial images, and how does that change with image conditions?
  2. RQ2. How completely and consistently can public product and ingredient data be cleaned and standardised to support restricted-ingredient filtering?
  3. RQ3. Does a constraints-first, weighted content-based recommender return relevant products while never violating explicit user constraints?
  4. RQ4. Do plain-language explanations make recommendations understandable to users?

Out of scope: medical diagnosis or treatment advice, predicting skin type from images, live price tracking, and collaborative filtering that needs user history.

M1, input and validation. Skin type, sensitivity, up to four concerns, category, budget, ingredient families and specific ingredients to avoid, and preferred ingredients. Impossible entries, such as a minimum above the maximum or an ingredient both preferred and avoided, are rejected.

M2, facial image. In-browser face detection (MediaPipe BlazeFace) and quality checks: resolution, brightness and a Laplacian-variance focus score. The photo is never uploaded. The transfer-learning CNN for visible characteristics is in Phase 3 and is not used in scoring until it has been evaluated.

M3, ingredients. Lower-case, strip percentages and symbols, split on commas outside brackets, map synonyms (aqua ↔ water, parfum ↔ fragrance, avobenzone ↔ butyl methoxydibenzoylmethane), exact-match against EU CosIng, then RapidFuzz (ratio ≥ 93). Each ingredient is tagged with families and concern associations.

M4, filter and score. C is the mean concern strength (1 for a targeted active, 0.5 for a supporting ingredient). I is the share of preferred ingredients present. K is the retailer's skin-type label fit. B is higher for cheaper prices inside the range. Components without user input are dropped and the remaining weights renormalised.

M5, explanations. Category and budget fit, the ingredients behind each concern, preferred ingredients found, confirmation that avoided items are absent, skin-type label, rating, and warnings such as partial lists, pregnancy-caution ingredients and patch-test reminders.

Synthesis. Facial skin analysis works but is narrow: the acne studies cover one condition and report moderate scores. Ingredient information adds value but is uncertain: its outputs are associations, not guaranteed outcomes. Recommendation design decides whether results are usable: collaborative methods need interaction data, while constraint-first, content-based designs work for a new user who supplies only a profile. Hansanie and Silva (2024) combine a CNN for acne severity with an ontology and report 87.5% accuracy in a 24-person survey.

Gap statement. The central gap is the practical implementation and systematic evaluation of a personalised, ingredient-aware and explainable skincare recommendation workflow. It combines estimates of visible facial skin characteristics with questionnaire-based user requirements, while accounting for dataset limitations, model reliability and incomplete product information.

Ethics, privacy and limitations

  • Privacy. Photos and answers are processed in the browser only and are never uploaded or stored.
  • No medical claims. Every page states that results are informational guidance.
  • Bias and data limits. Lighting, camera and skin tone affect images. Ingredient lists may be outdated, and ingredient presence does not prove effect.
  • Licensing. Only datasets whose terms permit reuse. Nothing is scraped.

Tools

Python, pandas and RapidFuzz for the data pipeline. Vanilla JavaScript for the recommender, shared by the website and the Node evaluation script. MediaPipe Tasks Vision for face detection. GitHub Pages hosts the site. The report proposed Streamlit; a static site was chosen so the prototype runs on any phone with no server, and the Python pipeline remains the source of truth for the data.
